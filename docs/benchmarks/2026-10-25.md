# Benchmark: Claude vs DeepSeek vs Auto (2026-10-25)

The figures behind [Token balancing](../../README.md#token-balancing). Raw rows: [2026-10-25.jsonl](2026-10-25.jsonl).

## Method

- **Suite:** the extension's own eval (`npm run eval`, `src/test/eval/`). Each task is a small repository with a bug, feature or refactor to do; the agent gets a plain-language prompt, and hidden tests it never sees decide pass or fail.
- **Tasks:** 5 standard (`bug-memo-race`, `feat-retry`, `refactor-move`, `fix-tests-queue`, `write-tests-cart`) and 3 hard (`hard-cross-module`, `hard-misleading-trace`, `hard-wide-refactor`).
- **Arms:**
  - `All-Claude`: `mode: claude`, Thinking effort, the Claude Code default model on the test machine (not pinned).
  - `All-DeepSeek`: `mode: deepseek`, V4 Pro at Thinking effort.
  - `Auto 50/50`: `mode: auto`, `tokenSplit: 50`.
- **Runs:** 2 per task and arm (46 runs in all); `hard-wide-refactor` has 1 run on Claude and DeepSeek because the run was stopped early.
- **Cost:** what each provider's token prices give for the tokens used, as the extension records it ([MODELS.md](../../MODELS.md)). For Claude this is the API price; on a Claude subscription you pay a flat fee instead.

```
npm run eval -- --arms baseline,ds-pro,auto --arm-json auto='{"mode":"auto","tokenSplit":50}' \
  --tasks bug-memo-race,feat-retry,refactor-move,fix-tests-queue,write-tests-cart,hard-cross-module,hard-misleading-trace,hard-wide-refactor \
  --k 2 --budget 30
```

## Failures

- **`bug-memo-race`, DeepSeek (both arms, 1 of 2 runs each):** a concurrency bug (two calls for the same key must share one run). DeepSeek reported the fix as done, but the hidden race test failed.
- **`hard-cross-module`, Claude (2 of 2 runs):** the rule for a derived flag lives in another module. Claude reported done both times; the hidden test failed on `urgent must be true only for priority 9-10`.

## Limits

- 8 tasks and 1-2 runs each: a single run flips a cell. Read the totals, not single cells.
- The fixtures are small repositories. Long-context work (large repositories, long sessions) is not covered.
- The Auto arm ran almost entirely on DeepSeek: under a split, each new task goes to whichever provider's stint it is, counted from the day's usage, and here that was DeepSeek's. It measures the split as configured on that day, not routing by task type.
- Routing by task type (`tokenSplit: null`, `claudeRole: primary`) was not run.
